# DataCollector

Платформа для сбора, валидации и надежного сохранения рыночных данных (Market Data: котировки, сделки, стаканы заявок L2/L3) с криптовалютных бирж (на начальном этапе, так как api таких бирж доступный)  (в текущей реализации — KuCoin UTA WebSocket).

---

## 1. Назначение и бизнес-цель

Система решает задачу сбора рыночных потоков для аналитических и исследовательских задач:

* **Количественные исследования:** анализ рыночной микроструктуры, расчет статистических метрик и поиск торговых сигналов.
* **Машинное обучение (Machine Learning & Data Science):** формирование непрерывных датасетов для обучения предиктивных моделей.
* **Бэктестинг (Backtesting):** воспроизведение исторических торгов с точностью до конкретного тика и состояния стакана.
* **Аналитика ликвидности:** отслеживание глубины рынка и плотности ордеров во времени.

### Ключевая инженерная задача
Обеспечить сбор данных с гарантией **отсутствия скрытых потерь (no silent data loss)** и полной верифицируемостью:
* **Контроль непрерывности (Gap Detection):** валидация последовательностей номеров (`sequence ID`) биржевых сообщений в реальном времени.
* **Восстановление целостности:** автоматический реконнект, переподписка и повторный запрос моментального снимка стакана (Orderbook Snapshot) при выявлении разрыва цепочки.
* **Идемпотентность пайплайна:** устойчивость к дублирующим событиям при сбоях сети или брокера.

## 2. Типовая архитектура

Система построена по двухконтурной модели с четким разделением управления и обработки потоков данных:

```
[ Внешние клиенты / UI ]
           │ (HTTP / REST)
           ▼
┌───────────────────────────────────────┐
│     Control Plane (control-plane)     │
│   - Управление подписками (REST API)  │
│   - Валидация торговых пар и лимитов  │
│   - Публикация Desired State          │
└──────────────────┬────────────────────┘
                   │
                   ▼  (Kafka Control Topic, compacted)
┌───────────────────────────────────────┐
│      Data Plane Gateway (connector)   │
│   - Акторная модель пула соединений   │
│   - WebSocket-клиенты к бирже (Netty) │
│   - Побайтовая фильтрация фреймов     │
│   - Контроль пингов и реконнекты      │
└──────────────────┬────────────────────┘
                   │
                   ▼ (WebSocket Stream)
            [ Биржа KuCoin ]
```

### Модули монорепозитория:
* **`control-plane` (Контур управления):**
  Отвечает за бизнес-логику управления сбором: регистрацию инструментов, прием команд на подписку/отписку через REST API и трансляцию желаемого состояния в компактные топики Kafka (Kafka Control Topics).

* **`connector` (Шлюз сбора данных):**
  Сетевой контур взаимодействия с биржей. Реализован на базе реактивной акторной модели:
  * `GroupPoolActor` — управляет распределением торговых пар по пулу физических WebSocket-соединений с учетом лимитов биржи на один сокет;
  * `ConnectionActor` — изолированное физическое соединение: контроль рукопожатий (handshake), фоновые ping/pong heartbeats, побайтовая фильтрация служебных ответов и публикация рыночных данных в Kafka.

## 3. Технологический стек

* **Платформа:** Java 25
* **Сетевой стек и реактивность:** Spring Boot 4, WebFlux
* **Брокер сообщений и оркестрация:** Apache Kafka
* **Контейнеризация:** Docker
